# Issue·PR 정리 현황

**Continuous issue and PR triage**는 [관리자용 현황 Issue #27](https://github.com/Maokami/pl-semantics-seminar/issues/27) 하나를 갱신합니다.
교재 수정안을 만드는 **Continuous reader feedback**와 역할이 다릅니다.

## 무엇을 정리하나요?

- 열린 Issue와 PR의 목적, 진행 상태, 막힌 이유와 다음 행동을 한국어로 요약합니다.
- 해결 근거가 있는 Issue, 중복 가능성이 있는 글, 추가 설명이 필요한 요청을 구분합니다.
- PR은 현재 커밋의 검사 결과와 리뷰를 확인해 관리자의 검토 순서를 제안합니다.
- 최근 갱신된 닫힌 PR 20개를 참고하고, 필요하면 원래 의견에 연결된 과거 PR도 읽습니다. 저장소 전체 이력을 모두 검증했다고 주장하지 않습니다.
- gh-aw가 관리하는 진단 기록은 일반적인 오래된 Issue와 구분합니다. 예를 들어 #6 Detection Runs는 자동 정리 대상으로 추천하지 않습니다.

## 언제 실행하나요?

사람이 Issue를 만들거나 수정·재개·종료하거나 라벨을 변경할 때, Issue/PR 대화 댓글을 작성·수정·삭제할 때 실행합니다. PR 생성·변경·종료도 별도의 권한을 제한한 작업이 검토를 요청합니다. 교재 게시나 독자 의견 후속 검사가 성공하면 최신 상태를 재확인합니다.

매일 **10:17 KST (01:17 UTC)**에도 확인하며, Actions에서 수동 실행할 수 있습니다. PR의 인라인 리뷰처럼 별도로 연결하지 않은 사건은 이 재확인에서 반영됩니다. GitHub 실행 대기열에 따라 지연될 수 있습니다.

연속 사건은 모아서 처리하고, 현황을 만드는 작업은 한 번에 하나만 실행합니다. 열린 항목의 내용·댓글·리뷰·현재 커밋 검사와 최근 닫힌 PR이 그대로라면 AI를 호출하지 않습니다. 현황 Issue 자체의 변경과 봇의 댓글은 직접 재실행을 일으키지 않습니다. 성공적으로 게시된 현황의 스냅샷 표식으로 중복 검토를 방지합니다.

## 관리자는 어떻게 결정하나요?

현황의 링크로 원래 글을 열어 근거를 확인한 뒤 **Close/Reopen** 또는 **Merge**를 선택합니다. 필요한 경우 원래 글에 사유를 남깁니다. 현황의 체크 표시나 댓글만으로 작업이 실행되지는 않습니다.

AI는 원래 Issue·PR을 닫거나 병합하지 않고 라벨·담당자·원고를 변경하지 않습니다. 쓰기 권한은 지정된 현황 Issue의 본문 갱신으로 제한합니다. 원래 글과 관리자 댓글은 보존합니다. 현황 본문은 다음 실행에서 교체되므로 관리자 메모는 댓글에 남기세요.

현황 Issue를 Close하면 이후 AI 갱신을 멈춥니다. Reopen 후 **Continuous issue and PR triage → Run workflow**로 재개할 수 있습니다. 워크플로 자체를 비활성화하면 사건 확인 작업도 멈춥니다.

## 검증과 비용

AI 작업은 읽기 전용 GitHub 도구로 근거를 확인하며 PR 코드를 내려받아 실행하지 않습니다. PR 사건을 받아 재검토를 요청하는 작업에도 체크아웃·AI 비밀 키를 두지 않습니다.

한 실행의 주 AI 세션은 USD 1, 24턴, 12분으로 제한합니다. 별도 위협 검사와 Actions 사용량을 포함한 총비용 상한은 아닙니다. 현황에 실제로 확인한 근거와 확인하지 못한 부분을 적으며, 자동 검사 성공을 수학적·편집상 승인으로 해석하지 않습니다.

AI가 실행된 경우에는 별도의 **Verify maintenance dashboard publication** 작업이 현황 본문에 해당 실행과 스냅샷 표식이 실제로 게시됐는지도 확인합니다. 갱신이 생략되면 원래 AI 실행이 초록색이어도 이 검사는 실패합니다. 같은 목록이라 AI를 생략한 실행에는 게시를 요구하지 않습니다.
